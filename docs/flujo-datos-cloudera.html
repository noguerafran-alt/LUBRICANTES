Un día cualquiera

Cuándo se mueve cada cosa

06:00

El celu corre la recolección de casa: fetch y reset del clon, tiendas, SEPA, series, dólar, Correo (si hay credenciales) y energía (solo si la SE publicó algo nuevo). Después hace un commit datos AAAA-MM-DD: casa (…) y push.

10:00

La Action de GitHub ve la fila casa de hoy y corre solo Mercado Libre. Si no la ve, corre todo como respaldo.

a demanda

Se carga el relevamiento de Grok por la pestaña Cargar y el server lo comitea a data/grok/.

min 20

Cada hora el celu hace pull de main. Si cambió el commit, recarga los datos sin reiniciar. Si cambió server.py, el vigía de CELU-SERVIDOR reinicia el servicio.

cada push

Render redeploya y recalcula todo al arrancar.

Desfase de hasta una hora. Un merge a main llega a Render enseguida, pero al celu recién en el próximo pull (minuto 20). Pasó el 27/11: el celu siguió mostrando el índice viejo hasta el pull. Para saber qué versión sirve cada uno, compará el commit de /salud en los dos.

No se inventan datos

Si una fuente se cae ese día, no se escribe fila y no se arrastra el precio anterior. El visor muestra la fecha del hueco y el error.

No se adivina el producto

Un aviso solo toma producto_id cuando hay exactamente un candidato (EAN o regex de seed/alias.csv).

Solo lo relacionado con YPF

Se guarda un producto YPF o un equivalente de seed/equivalencias.csv. Lo demás solo se cuenta.

Las fuentes no se mezclan

Ninguna mediana junta fuentes, países ni monedas. El índice YPF = 100 usa la mediana por aviso de 3 días.

Cloudera

Cómo meterlo en Cloudera

Hoy el paquete de Power BI se baja y se sube a mano a SharePoint, por ciberseguridad, y Cloudera quedó para después. El servidor ya tiene lo que Cloudera necesita: lectura abierta sin clave, ningún secreto en los GET y un zip con nombres fijos. Falta el lado de Cloudera.

Recomendado · camino A

Un Job de CML que baja el paquete todos los días

Cloudera solo lee. La recolección queda afuera, igual que hoy.

  1. En el proyecto de CML, crear bajar_lubricantes.py con el script de abajo. Usa solo la stdlib y no lleva claves.
  2. Crear un Job que lo corra a las 11:30 ART, cuando ya pasaron el celu (06:00) y la Action (10:00).
  3. El script revisa /salud, baja /api/bi/paquete.zip del celu (o de Render si el celu no responde) y deja los CSV en lubricantes/actual/ y en una carpeta por fecha.
  4. Opcional: con Spark, pasar los CSV a tablas de Impala o Hive (lub_precios, lub_indice…) para que Power BI lea de Cloudera en lugar de SharePoint.
Después · camino B

Correr el visor entero dentro de CML

Es lo que se hizo con MAPA-NEGOCIO («modo espejo»). server.py es solo stdlib, así que arranca como Application de CML sin instalar nada.

  • Necesita data/ y seed/ crudos, no el paquete. El repo es privado: habría que darle a CML un token de solo lectura, o sumar un endpoint /api/bajada.zip como el de MAPA-NEGOCIO.
  • La carga de Grok tiene que quedar apagada en Cloudera (sin clave ya se rechaza).
  • Conviene recién cuando el camino A esté andando y ciberseguridad apruebe el acceso.
# bajar_lubricantes.py - Job diario de CML. Solo stdlib, sin claves (lectura abierta).
import io, json, os, sys, urllib.request, zipfile
from datetime import datetime, timezone

SERVIDORES = ["https://lubricantes.fln-data-analysis.com",   # celu, principal
              "https://lubricantes-ypf.onrender.com"]         # respaldo (tarda en despertar)
DESTINO = os.environ.get("LUB_DESTINO", "/home/cdsw/lubricantes")

def bajar(base, ruta, timeout):
    req = urllib.request.Request(base + ruta, headers={"User-Agent": "cml-lubricantes/1"})
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return r.read()

def un_servidor():
    """Salud y paquete del MISMO servidor, para no mezclar versiones."""
    errores = []
    for base in SERVIDORES:
        try:
            salud = json.loads(bajar(base, "/salud", 90))
            if salud.get("ok"):
                return base, salud, bajar(base, "/api/bi/paquete.zip", 300)
            errores.append(f"{base}: /salud sin ok")
        except Exception as e:
            errores.append(f"{base}: {e!r}")
    sys.exit("ningun servidor respondio:\n" + "\n".join(errores))

base, salud, crudo = un_servidor()
hoy = datetime.now(timezone.utc).strftime("%Y-%m-%d")
for carpeta in (os.path.join(DESTINO, hoy), os.path.join(DESTINO, "actual")):
    os.makedirs(carpeta, exist_ok=True)
    with zipfile.ZipFile(io.BytesIO(crudo)) as z:
        for nombre in z.namelist():
            datos = z.read(nombre)
            if nombre.endswith(".csv"):  # sin BOM: Spark lo pegaria al nombre de la primera columna
                datos = datos.decode("utf-8-sig").encode("utf-8")
            with open(os.path.join(carpeta, nombre), "wb") as fh:
                fh.write(datos)
print(f"ok: {base} commit {salud['commit']} ultimo_dato {salud['ultimo_dato']} -> {DESTINO}")

Antes de armarlo, verificar desde la red de YPF

  • Que CML tenga salida a internet y llegue a lubricantes.fln-data-analysis.com: con curl -s https://lubricantes.fln-data-analysis.com/salud en una sesión de CML tiene que devolver {"ok": true, …}. Que el dominio fln abra desde YPF ya se vio con A4D en Oracle. Este host pasa por Cloudflare y no se probó.
  • Si el proxy de YPF exige configuración, definir HTTPS_PROXY en el proyecto. urllib lo toma solo.
  • Que ciberseguridad apruebe bajar datos de un dominio externo. Es lectura pública y sin credenciales; los datos no salen de YPF.
  • El paquete pesa ~1 MB comprimido (precios.csv ~8 MB, ~51 mil filas) y tarda ~1 s en armarse.
